# COA Reviewer — runtime dependencies, exactly pinned.
#
# This is what the updater builds each release venv from. Pins are ``==``, not
# ``>=``, on purpose: a deploy must install exactly what was tested. An
# unpinned deploy can pull a new transitive release between staging and switch
# and fail its health check for reasons that have nothing to do with the code
# change — and the automatic rollback would then blame the wrong commit.
#
# install.bat / install.sh keep their ``>=`` floors. Those set up a person's
# machine, where current packages are what you want. tests/test_install_scripts.py
# keeps the three files in lock-step and fails if a pin here drops below a
# floor declared there.
#
# Versions captured from the live COA environment (system Python 3.14.4 on
# ASAPSV1) on 2026-08-21 — the set the app was actually running against.
#
# To refresh: install into a clean venv, verify /healthz, then re-freeze.
